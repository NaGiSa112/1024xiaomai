# 工程笔记：踩过的坑与设计取舍

> 这些是开发过程中真实遇到的问题和解决办法，写下来一方面防止重踩，另一方面也是"为什么代码长这样"的说明。

## 一、运行环境限制

| 现象 | 根因 | 解决 |
|---|---|---|
| `pip install` 必失败：`OSError: [Errno 13] Permission denied ... pip-unpack-xxx.whl` | 宿主沙箱禁止在临时目录删除/重命名已解包文件，pip 的原子重命名被拦 | 依赖改为**预解包包树** `pkgs/` + `PYTHONPATH` 挂载；新包用 `scripts/add_pkg.py`（查 PyPI → 下 wheel → 直接解包） |
| `multiprocessing.Pool` 报 `WinError 5` | 沙箱禁止创建命名管道 | `sandbox_compat.py` 把 `Pool`/`ThreadPool` 替换为串行实现，`workers=0` |
| `.ps1` 报"意外的标记"、中文变乱码 | Windows PowerShell 5.1 对**无 BOM** 的 UTF-8 文件按 ANSI(GBK) 解码 | 所有含中文的 `.ps1` 存为 UTF-8 **带 BOM**；路径拼改用 `$PSScriptRoot`，不硬写中文路径 |
| `cv2.imread` 返回 None | OpenCV 在 Windows 下不支持非 ASCII 路径 | 统一用 `np.fromfile + cv2.imdecode` / `cv2.imencode + tofile` |
| Python 直连 github/zenodo 报 `CERTIFICATE_VERIFY_FAILED` | 本机 Python 默认 CA 缺中间证书 | `env.ps1` 设 `SSL_CERT_FILE` 指向 `certifi` 的证书包 |
| git 访问 GitHub 失败：`schannel: AcquireCredentialsHandle failed` / `error adding trust anchors` | schannel 后端在本机不可用；openssl 后端又读不了中文路径的 CA | 便携 git 改 `http.sslBackend=openssl`；`env.ps1` 把 CA 复制到 ASCII 临时目录并导出 `GIT_SSL_CAINFO`；代理走 `http.proxy` |

## 二、训练与推理的取舍

| 决策 | 原因 |
|---|---|
| **分辨率固定 1024** | 图像原生 1024；训练 1280 属于上采样，慢 1.56 倍而收益有限。队友实测 640→1024 有 +1.1 点，1024 往上就很小了 |
| **`cache=ram` + `batch` 适中** | 实测把 65 s/epoch 压到 38 s（-42%），瓶颈是 CPU 解码而不是 GPU；900 张 1024 图只占约 2.2 GB 内存 |
| **`close_mosaic=20`** | 小数据集末期关掉马赛克，让模型在真实分布上收敛，通常再 +0.3 |
| **推理 `conf=0.001`** | 评测走完整 PR 曲线，截断高置信度会直接掉分（队友首版误用 0.25，掉了 3 个点） |
| **不开翻转 TTA** | 队友多组实测 TTA 全线掉点；真正有效的是**多尺度**推理（+0.0066） |
| **同族模型不做无限集成** | 同架构多模型集成增益会饱和（实测 +0.0001），必须跨骨干 / 跨分辨率 |
| **900 全量训练 vs 干净 val** | 官方 val 只有 100 张，选型容易过拟合；最终冲分时把 val 并入训练（历史 +1 点），改用 5 折 OOF 做干净评估 |

## 三、评测与提交

| 问题 | 处理 |
|---|---|
| 导出坐标/字段顺序错 | 额外写一套 `eval_submission.py`，用导出的 txt **独立复算 mAP@0.5**，和 ultralytics 官方 val 交叉验证（实测差 0.009） |
| 提交 txt 换行符 | Python 默认写 CRLF，某些平台的解析器会把 `\r` 粘到最后一个字段；`predict.py` 强制 `newline="\n"`，`make_submission.py` 再兜底归一化 |
| 提交文件命名/数量对不上 | `make_submission.py` 会核对测试图清单与 txt 一一对应，缺一个就报错退出 |
| 5 折 OOF 的 GT 路径 | 折内 val 混了 train/val 两个划分，GT 需按图片路径把 `images` 段换成 `labels` 段解析 |

## 四、数据层面

- **密度分层切折**：单图框数 1~190，随机切分会让某折集中出现稠密图，OOF 指标噪声变大；按密度分位数分层后每折 val 密度 42.4~44.1，几乎一致。
- **同源筛查**：只用感知哈希会误判（麦田纹理高度相似），必须做**像素级确认**（缩图 128×128 算 MAD）。两段式：dHash 取 top-3 候选 → 像素 MAD < 6/255 判定同图。
- **外部数据标签口径差异**：同一张图，官方标注框数与本机 GWHD 标注不一致（如 64 vs 53），所以外部数据只用于预训练，最终必须回官方数据微调。

## 五、硬件与稳定性

| 现象 | 处理 |
|---|---|
| 显存接近上限时训练卡死（GPU 100% 但功耗很低） | 按实测单图占用反推 batch：`可用显存 = 空闲 - 3 GB`，再除以单图占用；`run_long.ps1` 启动时自动算 |
| 训练进程被系统杀掉（`exit -1`，无 traceback） | 每 epoch 都存 `last.pt`；脚本检测到 `last.pt` 就 `--resume-from` 续训；每阶段"产物存在即跳过"，重跑等于续跑 |
| 中途被要求让出 GPU | 直接把 run 目录改名为 `*_partial_epN`，避免后续脚本误认为"已完成"而用到半成品权重 |
