## 一、核心发现：赛题数据是 GWHD 的子集

**方法**：dHash 取最近 3 候选 → 缩图 128×128 算像素 MAD → **MAD < 6/255 判定为同一张图**的重编码版本。
（只用 dHash 会误判：麦田纹理太像，64 bit 感知哈希在"距离≤6"这档假阳性很多。第一版没做像素确认时得到 434/58/47，做了确认后**数字没变**，说明这批确实是同一张图。）

| 划分 | 总数 | 同图重编码 | 占比 | 代表样例（MAD） |
|---|---|---|---|---|
| train | 800 | **434** | 54.2% | `train/0003` ↔ `f94718a9b.jpg`（1.6） |
| val | 100 | **58** | 58.0% | `val/0001` ↔ `6a7cbd408.jpg`（1.0） |
| test | 100 | **47** | 47.0% | 见 `docs/重叠检查.md` |

**但标注口径不同**：同一张图，赛题标注比 GWHD 多/少若干框。

| 图 | 赛题框数 | GWHD 框数 |
|---|---|---|
| train/0003 | 64 | 53 |
| train/0005 | 33 | 35 |
| train/0029 | 72 | 75 |
| val/0002 | 75 | 81 |

### 三个直接推论

1. **外部数据不是"相似领域"，是同分布扩增**：GWHD 里还有 **2834 张**与赛题 1000 张完全不重复的图（同一批田间图、同样的 1024×1024、同样的单类麦穗）。相对 900 张训练数据是 **3.1 倍**增量。这是本任务唯一的"数据杠杆"，其余技巧都是小数点后的竞争。
2. **标签口径有差异 ⇒ 不能纯外部数据训完直接交**：必须在赛题 900 张上微调，把输出分布拉回官方口径。这也解释了为什么"预训练 + 微调"比"直接把 GWHD 混进来一起训"更稳。
3. **test 与 train/val 同源 ⇒ 本地 val 是可靠代理**：这印证了我之前的判断（test 与 val 的图像统计、检出密度几乎一致）。所以本地 val 涨点能带到线上，之前"线上比本地低 3 点"主要是 TTA 掉点 + 在 100 张 val 上反复调参造成的乐观偏差。

### 合规处理（已落地）

赛题规则：「测试集仅可用于输出最终推理结果，不可以任何形式参与训练过程」。
既然 GWHD 里有 47 张与测试图同一张图的版本（且带标注），**它们必须排除**。

`scripts/build_gwhd_clean.py` 已生成干净清单：

```
赛题 1000 张  vs  GWHD 3373 张
剔除同源 539 张（train 434 / val 58 / test 47）
→ data_external/gwhd_clean_train.txt   2834 张
→ data_external/gwhd_clean.yaml
```

> 报告里可以直接引用这个筛查过程，作为"未使用测试集"的证据。

## 二、涨点清单（按性价比排序）

| 优先级 | 手段 | 预期 | 代价 | 依据/状态 |
|---|---|---|---|---|
| **P0** | **GWHD-clean 预训练 → 900 微调** | **线上 +1~3 点** | 2~2.5 h 预训练 | 同源 3.1× 数据，本笔记第一节 |
| **P0** | **900 全量 + 长 schedule + close_mosaic** | +0.8~1.2 | 已在计划里 | 队友实测 800→900 线上 +1.01；末尾关马赛克 +0.3 |
| **P1** | **容量 l / m / x** | +0.3~0.8 | 时间线性增加 | 队友 n→s +0.38；同族外推 |
| **P1** | **多尺度推理 + NMS 融合** | +0.5~1.0 | 推理 ×3，几分钟 | 队友实测 896+1280 比单 1024 高 +0.0066（本地） |
| **P2** | **model soup（权重平均）** | +0.2~0.5 | 零训练，10 min | 免费午餐：把最后 N 个 epoch 的权重做平均，通常优于单一 best.pt |
| **P2** | **多 seed / 多折集成** | +0.5~1.0 | 训练 ×N | 跨架构才不饱和（队友同族集成 +0.0001） |
| **P3** | **P2 检测头**（stride=4 增加一层） | +0.2~0.6 | 训练慢 ~30%，需改 yaml | 小目标常规手段；我们的目标 68 px，属于"中小"不是"极小"，预期有限 |
| **P3** | **SAHI 切片推理** | +0~0.5 | 推理 ×2~4 | 密集场景有效；但 68 px 目标在 1024 输入下已够大，先测再说 |
| **P4** | 软 NMS / 框尺寸微调（±3%） | +0~0.3 | 推理侧 | 应对"test GT 口径"差异的对冲 |
| **排除** | 翻转 TTA | **负收益** | — | 队友多组实测 TTA 全线掉点 |
| **排除** | Copy-Paste | 不可用 | — | 纯框标签无 segments，ultralytics 会静默跳过 |
| **排除** | 同族模型无限堆集成 | 饱和 | — | ens5 相对 ens4 只 +0.0001 |

### 关于"能不能用 GWHD 标签直接标 test 图"

**不能**。虽然 47 张测试图在 GWHD 里有对应标注，但那就是测试集标注，用它训练/调参 = 测试集参与训练，直接违规（课程作业层面也是学术不端）。我们只把它用于**排除**，不用于得分。

## 三、文献参考（用于报告背景）

- GWHD 官方论文（2020，arXiv:2009.11977）给出了 GWHD 数据集上的基线：主流检测器 mAP 视年份/划分在 0.75~0.9 区间，密集小目标仍是主要误差来源。
- 近两年针对麦穗的改进工作集中在：更高输入分辨率、注意力/多尺度特征融合、专用小目标检测头（如 [改进 YOLOv11 的田间麦穗检测](https://link.springer.com/article/10.1007/s44163-026-01755-6)、[Agriculture 2025 的 YOLOv11 改进](https://openurl.ebsco.com/EPDB%3Agcd%3A3%3A18690899/detailv2?sid=ebsco%3Aocu%3Arecords&id=ebsco%3Adoi%3A10.3390%2Fagriculture15161765)）。
  这些工作的增益多在 +1~3 个点，且**大多建立在"更多数据 + 更高分辨率"之上**，与我们的 P0 判断一致。
- 结论：与其花一晚改网络结构，不如把同源数据吃满。
