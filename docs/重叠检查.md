# 赛题数据 vs GWHD 同源核查

GWHD 参照库（本机）：**3373** 张 1024×1024

判定口径：dHash 取最近 3 个候选 → 缩图 128×128 算像素 MAD → **MAD < 6/255 认定为同一张图**（PNG/JPEG 重编码级别的差异；不同图 MAD 通常 > 30）。

| 划分 | 总数 | 字节完全相同 | 同图（重编码） | 占比 |
|---|---|---|---|---|
| train | 800 | 0 | 434 | 54.2% |
| val | 100 | 0 | 58 | 58.0% |
| test | 100 | 0 | 47 | 47.0% |

## 结论

- 训练集有 **54%** 的图能在 GWHD 里找到同一张图的重编码版本，验证集 **58%**，测试集 **47%**。
- 说明赛题数据与 GWHD **同源同分布**（同一批 1024×1024 田间图），不是「相似领域」。
- 但**标注不同**：同一张图，赛题标注框数与本机 GWHD 标注框数不一致（例如 train/0003 赛题 64 框 vs GWHD 53 框）。⇒ 外部数据的**标签口径有差异**，适合用来预训练学特征，最后一律在赛题 900 张上微调对齐口径。
- **合规红线**：与 test 同源的那些 GWHD 图（及其标签）**一律排除出训练集**，不使用任何与测试图对应的标注，避免「测试集参与训练」。详见 `scripts/build_gwhd_clean.py`。

## 追加核查：GWHD2021 全量包（更精确的口径）

后来从 ModelScope 拿到了官方全量包 `gwhd_2021.zip`（6515 张图 / 275,458 个框），改用**更强的判定口径**再核对一遍：

**判定方法**：把图片解码成 RGB numpy 数组，对数组取 **md5**。重编码（PNG↔JPEG）会改变文件字节，但**解码后的像素完全一致**，因此这是"同一张图"的确定性判据，不存在感知哈希的假阳性问题。

| 项 | 结果 |
|---|---|
| 赛题 1000 张在 GWHD2021 中命中 | **1000 / 1000（100%）** |
| 包含 test 100 张 | **全部命中** |
| GWHD2021 中与赛题重复 | 1000 张 → **全部剔除** |
| GWHD2021 中与旧外部集（GWHD2020）重复 | 676 张 → 剔除（避免重复训练） |
| **GWHD2021 中全新可用** | **4939 张** |
| 与旧干净集合合并后（v2） | **7770 张**（= 赛题 900 张的 8.6 倍） |

**这个结果说明什么**

1. 赛题的 1000 张图（含全部测试图）就是 GWHD2021 的原图——**测试集与外部数据同源，不是"分布相近"而是"同一批数据"**；
2. 因此用 GWHD2021 的其余 4939 张做预训练，等于在完全相同的采集条件、标注规范下扩容，这是理论上能拿到的最强数据杠杆；
3. 合规上更要注意：正因为同源，**必须**在训练前把与 test 相同的图剔除干净。本项目已用像素 md5 做到"零重叠"（`scripts/dedupe_exact.py` 的输出：`gwhd2021_dedupe_summary.json`）。

> 一点自我纠错：第一版筛查脚本用「dHash + MAD<6」在 6515×3373 规模上假阳性爆炸（把 5515 张全判成重复，全新数=0）。换成像素 md5 后才得到正确数字。判重口径必须在报告里写清楚。
